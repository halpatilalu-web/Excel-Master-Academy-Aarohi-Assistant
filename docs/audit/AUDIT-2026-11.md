## 1. CRITICAL — data loss / broken core promise

### C1. Workbook autosave dies after the first save (409), and edits are silently lost
**Evidence (measured):** typing into two different cells of *Free Excel Workbook* produced
`GET 200 → POST 201 → POST 409 → POST 409`, and the stored document still had the **first** edit only.

**Cause** — `src/lib/excel/useWorkbook.ts`:

- `persist()` always calls `add(payload)`; it never calls `update(docId, …)` even though `docId.current` is captured after the first save.
- `payload.id = docId.current ?? ""`, so every save is a *create*:
  - 1st save: id `""` → server assigns a uuid → 201 → `docId` set;
  - 2nd save: id = that uuid → `POST /api/c/excelWorkbooks` → **409 "a document with that id already exists"**;
  - the `catch {}` swallows it → the student sees a normal cell, and the write is gone.
- Because the error is swallowed, the offline `localStorage` copy is also never refreshed → after a reload the sheet shows older content than the screen did.

**Impact:** every practice sheet, the free workbook, and the desktop Excel keep only the *first* change made in a session. This is the most serious bug in the app.

**Fix (behaviour only, no UI):** save with `update()` when `docId` exists (and `add()` only for the first save); fall back to create-on-404; keep the existing optimistic local copy. Files: `src/lib/excel/useWorkbook.ts`.

### C2. Offline / dead-network start = permanently blank screen
**Evidence:** reload with network off → `document.body.innerText === ""`, no `[data-app-ready]`, no splash, nothing.

**Cause:** no service worker (app shell is never cached), so the document itself cannot load offline; and `AuthGate` shows the splash only while `checking`, after which:

- `GET /api/auth/me` fails → falls back to a **local guest** (`getOrCreateLocalGuest`) → app renders **but as a different user** than the student's server account, so their progress/exam history looks empty;
- the sign-in form is replaced by a local guest, with no way back to the server account until the network returns and the page is reloaded.

**Impact:** on a flaky connection or inside the APK with no data, the app opens empty (or, on the pre-auth path, not at all). Students read this as "my progress is gone".

**Fix:** cache the app shell (service worker with a versioned cache + offline fallback), and when `/api/auth/me` fails with *network* error keep the previously known account (and show the existing non-visual banner state instead of silently becoming a guest). Files: new `src/sw.ts` + `public/sw.js` registration in `main.tsx`, `src/lib/auth.ts`, `src/components/AuthGate.tsx`.

### C3. No protection against losing an unfinished marked sheet / exam
Currently there is no autosave of the in-progress exam answers and no guard on reload/back during an exam (the "Copy/edit" style dialogs are unrelated).

**Measured:** the exam timer is wall-clock based (`endAtRef = Date.now() + 20 min`) but **fires 4×/second via `setInterval`**; under a real background (page frozen 8 s, the Android app-switch case) the interval simply stops — after resuming, throttled/backgrounded time is dropped and the countdown is wrong (and answers were never persisted anyway).

**Fix:** `visibilitychange`/`focus` re-sync (`setLeft` from `Date.now()`), `beforeunload` guard while an exam runs, and persist answers in `sessionStorage` so a reload/back resumes the same attempt. Files: `src/views/Exam.tsx`.

## 2. HIGH — reliability and platform (Android WebView) behaviour

### H1. Android hardware Back button exits the app instead of navigating back
The app uses hash routing with `history` untouched for in-app navigation (`window.location.hash = …`), so the WebView's back gesture goes "one document back" and can leave the app from any deep screen. **Fix:** push a history entry per view and handle `popstate` (keeps exactly the same URLs and visual result; verified back/forward behaviour is in the test plan). Files: `src/App.tsx`.

Also relevant for the APK: no `safe-area` handling outside the bottom bar (notch/punch-hole and gesture bar areas), verified as `env(safe-area-inset-*)` used once (`src/index.css:264`).

### H2. Clipboard copies silently fail in the APK (non-secure origin)
`navigator.clipboard` needs a secure context. Inside an APK the WebView origin is often `file://` or `http://localhost`, where `navigator.clipboard` is `undefined` — `CopyBtn` (`src/views/Reference.tsx`, `src/views/Chapters.tsx`, `src/views/ProToolkit.tsx`) then does nothing but still flashes the ✓ tick, i.e. a *false* success. **Fix:** `document.execCommand("copy")` fallback + only show success when a copy actually happened. Files: `src/lib/clipboard.ts` (new), 3 call sites.

### H3. Download buttons can do nothing in the APK
`.xlsx` / `.csv` / JSON export all use `URL.createObjectURL` + `a.download` (`src/components/ExcelGrid.tsx`, `src/components/LiveSpreadsheet.tsx`, `src/data/labs.ts`, `src/lib/store.ts`, `src/lib/desktop/fs.ts`). WebViews without a `DownloadListener` drop these silently, and the old WebView would navigate away. **Fix:** feature-detect, catch the failure, and tell the student (toast with the existing tone classes) instead of a silent nothing; where `navigator.share`/Filesystem is available in the APK shell, use it. Files: `src/lib/download.ts` (new) + call sites.

### H4. Lesson / exam "in progress" state is lost on tab switch inside the APK
Covered by C3 + H1: exam answers and the running timer are memory-only.

### H5. `render` path ignores the API when Vercel serves only the SPA
`vercel.json` rewrites everything to `index.html`. `/api/*` is excluded from the rewrite, so on Vercel the API 404s → the app silently degrades to a *local* guest. That is by design, but it means the deployed Vercel URL has no accounts, no server progress and no certificates. **Decision needed from you:** is the Vercel URL a real deployment, or a preview? If real, it needs the backend URL wired (`VITE_API_BASE` + `APP_ALLOWED_ORIGINS`); today `/api` is hardcoded relative in `src/lib/api.ts`.

## 3. MEDIUM — performance

### P1. Entry chunk is 1,078 kB (344 kB gzip); ~10 routes' worth of code loads before the dashboard paints
Measured in the production build, the *entry* chunk contains (source sizes): `ExcelGrid.tsx` 166 kB, `diplomaModules.ts` 85 kB, `formulaCatalog.ts` 62 kB, `Desktop.tsx` 50 kB, the whole formula engine (~200 kB) and `Ribbon`/`Panels`/`SheetDialogs` — none of which the Dashboard needs.

Measured load (prod build, 390×844, 4× CPU, cold cache):
| Network | FCP | DOMContentLoaded | requests (JS) |
|---|---|---|---|
| Fast 4G | 2.5 s | 2.4 s | 3 |
| Slow 3G | 1.0 s | 1.0 s | 3 |

FCP is fine; the gap is **hydration + TTI**, not the network — the phone parses/executes 1 MB of JS it may not need (the Excel workbook is one tap away, the desktop panel is decorative on the dashboard).

**Fix (no visual change):** split real chunks with an explicit `manualChunks` function that groups `ExcelGrid`/`Ribbon`/`Panels`/`SheetDialogs` + the formula engine into an `excel` chunk and `Desktop`+`OfficeApps` into a `desktop` chunk; import `DIPLOMA_MODULES`/`AI_GALLERY` lazily where only the heavy view needs it. Target: entry ≤ 250 kB gzip.

### P2. `formulaPractice.ts` is 368 kB / 6,040 lines of drills — imported eagerly
Not in the entry chunk today (only the workbook/pro toolkit pull it), but it makes the workbook chunk heavy. Move the drill data behind a dynamic import for the lab? **Optional;** the current cost is only inside an already-lazy route.

### P3. 2.1 MB `public/ai-gallery` + 2.0 MB `public/audio` are shipped in the APK regardless of use
Audio is `preload="none"` (correct), but the APK carries all of it. **Optional:** keep, or move audio to the API host.

### P4. `update()` in `src/lib/store.ts` writes the same state twice per call
Two `setState` calls back-to-back (line with `merged && doc` is dead code) → double listener fan-out on every save. Harmless but pure waste; remove the first (dead) line.

### P5. 12 `<img>` elements, none with `loading="lazy"` / `decoding="async"`
Aarohi avatars and the AI gallery are all eager. **Optional, zero visual change.**

### P6. Every route transition re-runs the full-page `motion.div` fade
`AnimatePresence mode="wait"` with `initial/animate/exit` on a wrapper that mounts the whole view — fine, but it means the new view is mounted only after the old one's exit (200 ms extra on every navigation). Keep (it is the design), just noted.

## 4. SECURITY — what is already good, and the gaps

**Good (verified in code):** scrypt password hashing + per-user salts, SHA-256 session tokens stored hashed, HttpOnly cookies, SameSite handling, CSRF guard on cookie mutations (Origin/Referer/Sec-Fetch-Site), per-IP/email rate limits on login/signup/guest/assistant, strict CSP on the SPA response, owner-scoped documents, reserved `_` collections blocked, path-traversal guard on the static fallback, no secrets in the repo, `.env*` gitignored, `pnpm audit`/`pip-audit` clean.

**Gaps:**
| # | Finding | Severity | Fix |
|---|---|---|---|
| S1 | `CORSMiddleware(allow_origins=["*"])` on **all** routes. Safe for cookies (no credentials), but it lets any site read `/api/health`-style metadata and any bearer-less GET is still same-origin protected only by cookies — acceptable, but should be a configured allowlist when `APP_ALLOWED_ORIGINS` is set. | Medium | Restrict to the configured origins + `` (non-browser) when the env var exists. |
| S2 | No `Content-Security-Policy` for the **dev/static** case and no `Referrer-Policy`/`X-Frame-Options` on `/api/*` (only the SPA fallback gets CSP). | Low | Add the same headers in the middleware for every response. |
| S3 | Exam scores/certificates are client-computed and client-written (`POST /api/c/exams`). A student can send any score. | Medium | Server-side verification of the answer sheet (needs the question bank moved/shared) — **needs your decision**, because it changes the data contract for old attempts. |
| S4 | No "sessions list / revoke all" endpoint; password change does revoke others (good), but a stolen 30-day cookie cannot be listed. | Low | Optional `GET/DELETE /api/auth/sessions`. |
| S5 | Guest accounts are unlimited-per-device and can be re-created; the assistant endpoint is capped (20/min/user, 40/IP, 120 global) — already good, worth keeping an eye on with real keys. | Info | — |

No hardcoded keys, no personal data in logs, no `eval`, no `dangerouslySetInnerHTML` found in `src/`.
